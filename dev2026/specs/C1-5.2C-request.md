## 6. The gate — C1 contract validation under 5.2C

Variant **5.2C**, seed policy `both-pinned`, exactly as spec 008 §7c defines it.

**Seven things are verified, and they are reported separately:**

1. **canonicalised values identical** — both arms normalised to
   `(time_period, depth, lat, lon)` **numerically**, then every value compared exactly;
2. **column SEQUENCE identical** — not the column set. Column order is out of spec 008's
   scope, so it must not have moved, and a set comparison would not notice if it had;
3. **candidate rows conform** — the candidate's **raw** JSON and CSV responses already
   ascend by numeric `(time_period, depth, lat, lon)`, with at most one row per key.
   **Candidate only:** the reference does not implement the contract, and holding it to
   one it never adopted would manufacture failures;
4. **expected raw row-order differences recorded** — carrying **both arms'
   `row_order_sha256`**, so the difference is evidenced rather than asserted;
5. **the raw difference is proved to be a permutation and nothing else** — the
   **reference's own** data rows, permuted into contract order, reproduce the
   **candidate's bytes exactly**. CSV: header fixed, data lines permuted, line
   terminator preserved. JSON: the top-level array split at element boundaries, raw byte
   slices carried across, never re-serialised. Both are **self-checked** first by
   reassembling the reference's original order and requiring it to reproduce the
   reference's original body;
6. **byte-exactness still required where no ordering difference is possible** — non-row
   payloads (the OpenAPI document), error responses, single-row responses, and multi-row
   responses whose reference was **already** in contract order. A byte difference in any
   of these is a **regression**;
7. **reconstruction that cannot be completed ⇒ `INCOMPLETE_VALIDATION`** — not a PASS,
   non-zero exit, and **no deployment claim may rest on it**.

**`N/A`, neither pass nor failure:** responses with no row order — error bodies, non-row
payloads, zero-row results — are recorded `applies: false`, `ok: null`, and counted
apart. Scoring them as passes would let a run in which every case errored report a
perfect order gate.
